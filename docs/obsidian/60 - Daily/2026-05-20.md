## 💡 Aprendizados

### Sobre ambientes de shell
- **Pydantic-settings dá precedência a env vars do OS sobre .env**. Uma var `FOO=""` no shell silenciosamente vence um `FOO=valor` no `.env`. Para projetos que dependem do .env como verdade, considere `env -u FOO …` no comando de boot OU forçar leitura com `dotenv_values()` direto.
- Apps de desktop (Claude for Desktop neste caso) podem **plantar variáveis vazias** no shell do usuário sem deixar rastro óbvio.

### Sobre merges com 2 sessões em paralelo
- Quando codex e Claude trabalham simultaneamente, é melhor cada um em uma branch dedicada. Codex preferiu patches in-tree no `main` → exigiu commit-de-snapshot antes do merge.
- 7 conflitos foram saudáveis: cada arquivo precisou de uma decisão consciente entre as duas abordagens. Não houve over-write cego.

### Sobre Force Execute
- Escape hatches são valiosos MAS precisam de hard rules. A regra "só funciona em paper ou testnet" é não-negociável porque:
  1. Operador pode marcar a caixa por engano em produção.
  2. Auditoria precisa diferenciar uma execução normal de uma com bypass.
  3. Override de risco em mainnet é uma decisão de ADR, não de checkbox.
