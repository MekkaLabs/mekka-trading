## Stories Implementadas

### Story 183 — RoleWorkingMemory
**Padrão:** MetaGPT `RoleContext.rc.memory` — working memory por Role

**Novo arquivo:** `src/services/role_working_memory.py`
**Modificado:** `src/agents/vision.py`

`RoleWorkingMemory` mantém uma janela deslizante (`deque(maxlen=N)`) de `CycleRecord` por símbolo:
`action`, `confidence`, `regime`, `outcome_pnl`, `cycle_id`.

`get_prompt_block(symbol, limit=5)` gera bloco formatado injetado no prompt Vision:
```
=== Recent Trade History: BTC (last 5 cycles) ===
  • LONG @ conf=75% | regime=VOLATILE | outcome=+120.50 USD
  • HOLD @ conf=55% | regime=SIDEWAYS | outcome=pendente
Use this history to avoid repeating recent mistakes and recognize recurring patterns.
```

`resolve_outcome(symbol, pnl)` permite atualizar o outcome de um ciclo pendente.

**Endpoints novos:** `GET /api/working-memory[?symbol=BTC]`

### Story 184 — TypedCycleMessage
**Padrão:** MetaGPT `Message(cause_by, sent_from, send_to, content)` — roteamento tipado

**Novo arquivo:** `src/models/cycle_message.py`
**Modificado:** `src/agents/nick_fury.py`

`CycleMessage` Pydantic com campos de roteamento espelhando MetaGPT:

| Campo MetaGPT | Campo Mekka | Exemplo |
|---------------|-------------|---------|
| `cause_by` | `stage` | `CycleStage.SIGNAL_EMITTED` |
| `sent_from` | `sender` | `"NickFury"` |
| `send_to` | `recipients` | `["Batman"]` |
| `content` | `payload_json` | JSON do TradingSignal |

NickFury emite dois `CycleMessage` por ciclo:
1. `ANALYSIS_DONE` antes do Vision (send_to=Vision)
2. `SIGNAL_EMITTED` após Vision (send_to=Batman)

Ambos são apenas log/instrospection — o pipeline não depende da emissão.

Factories: `from_signal()`, `from_analysis()`, `cycle_start()`, `cycle_end()`, `cycle_skipped()`.

### Story 186 — SignalOutcomeMemory
**Padrão:** MetaGPT `LongTermMemory` + similarity search

**Novo arquivo:** `src/services/signal_outcome_memory.py`
**Modificado:** `src/agents/vision.py`

`SignalOutcomeMemory` armazena `OutcomeRecord(symbol, regime, action, confidence, pnl_usd)`.
`find_similar(symbol, regime, action, top_n=3)` usa score de similaridade discreto (sem FAISS):

```
similarity_score = 0.0
if action match:   score += 0.4
if regime exact:   score += 0.6
if regime partial: score += 0.3   # "BULL" ↔ "STRONG_BULL"
```

`get_prompt_block(symbol, regime, action)` injeta no prompt Vision:
```
=== Past Performance: BTC (similar conditions) ===
Conditions matched: VOLATILE + LONG
  • LONG @ conf=80% | regime=VOLATILE → +120.50 USD
  • LONG @ conf=70% | regime=VOLATILE → -45.20 USD
Win rate in similar conditions: 50.0%
Consider this historical performance when setting confidence.
```

`win_rate(symbol, action, regime)` → float 0.0–1.0 para métricas.

### Story 187 — IncrementalCycleSkip
**Padrão:** MetaGPT Incremental Development — pula stages não afetados por mudanças

**Novo arquivo:** `src/services/cycle_incremental_guard.py`
**Modificado:** `src/agents/nick_fury.py`

`IncrementalCycleGuard` mantém um `CycleCheckpoint` (price, regime, signal, timestamp) por símbolo.
Antes de chamar Vision, `should_skip()` decide se o LLM call pode ser evitado:

```
Condições para SKIP (todas devem ser verdadeiras):
  1. Existe checkpoint anterior para o símbolo
  2. Δprice < price_threshold_pct (default 0.2%)
  3. current_regime == last_regime
  4. age < max_signal_age_s (default 120s)
  5. Existe sinal anterior válido para reutilizar
```

Quando skip=True → NickFury reutiliza o sinal do checkpoint sem chamar Vision.
Após Vision executar normalmente → `update()` grava novo checkpoint.

**Parâmetros configuráveis via settings:**
- `incremental_price_threshold_pct` (default 0.002 = 0.2%)
- `incremental_max_signal_age_s` (default 120s)

**Endpoint:** `GET /api/incremental-guard` → checkpoint por símbolo + skip_rate.
