## Stories Entregues

### Story 203 — CycleGroupChat + CycleGroupChatManager
**Arquivo:** `src/services/cycle_group_chat.py`
**Padrão:** AutoGen `GroupChat` + `GroupChatManager`

Roundtable multi-agente onde cada participante emite uma opinião por rodada. O manager executa `N`
rounds e aplica consenso por contagem de votos (LONG > SHORT > HOLD) ao final.

**Componentes:**
- `SpeakerSelectionMethod`: ROUND_ROBIN / RANDOM / CUSTOM
- `CycleGroupParticipant`: `opinion_fn(context, history) → str` (fallback: string formatada)
- `CycleGroupChat`: buffer compartilhado entre todos os participantes
- `CycleGroupChatManager.run_round()`: todos os participantes falam em cada rodada
- `get_consensus()`: conta menções LONG/SHORT/HOLD, retorna `majority_vote`

**Integração NickFury:** `_group_chat203` inicializado no `__init__`, disponível para
consenso pré-sinal.

### Story 204 — MekkaConversationSession
**Arquivo:** `src/services/mekka_conversation_session.py`
**Padrão:** AutoGen `ConversableAgent.initiate_chat()`

Sessões estruturadas entre dois agentes (initiator ↔ recipient) com max_turns, callback de
terminação e carryover de contexto entre sessões.

**Componentes:**
- `TerminationReason`: MAX_TURNS / TERMINATION_MSG / INITIATOR_TERMINATE / ERROR / NOT_TERMINATED
- `run(initiator_fn, recipient_fn, initial_msg, symbol, cycle_id)`: alterna A→B com verificação
  de terminação após cada reply de B
- carryover injetado no início: `"\n".join(carryover) + "\n\n" + initial_msg`
- Factory: `get_conversation_session(initiator_id, recipient_id, max_turns, is_termination_msg)`
  com chave `f"{A}:{B}"`

**Parâmetros do construtor:**
```python
MekkaConversationSession(
    initiator_id="VISION",
    recipient_id="BATMAN",
    max_turns=5,                          # AutoGen max_turns
    is_termination_msg=None,              # callback(msg) → bool
    summary_method="last_msg",            # last_msg | concat
    carryover=None,                       # List[str] injetado no início
)
```

### Story 205 — CycleTaskDefinition
**Arquivo:** `src/services/cycle_task_definition.py`
**Padrão:** CrewAI `Task` + `expected_output`

Tarefas declarativas com expected_output estruturado, validador customizável e context chaining
entre stages dependentes.

**Componentes:**
- `CycleTaskDefinition`: `task_id`, `description`, `expected_output`, `agent_role`,
  `context_task_ids`, `validator_fn`
- `CycleTaskChain.run_chain()`: itera task_ids, passa
  `previous_results[dep_id].raw_output` como `ctx[f"context_{dep_id}"]`
- `TaskResult.is_successful`: `status == COMPLETED AND validation_passed`
- `TaskStatus`: PENDING / RUNNING / COMPLETED / FAILED / SKIPPED

**Context chaining:**
```python
# Stage N→N+1: output do stage N disponível como contexto
ctx[f"context_{dep_id}"] = previous_results[dep_id].raw_output
```

### Story 206 — CyclePipelineOrchestrator
**Arquivo:** `src/services/cycle_pipeline_orchestrator.py`
**Padrão:** CrewAI `Process` + `Crew.kickoff()`

Executa pipelines de stages com modo SEQUENTIAL (cada stage recebe output do anterior) ou
HIERARCHICAL (skip condicional do stage IRONMAN quando action=HOLD).

**Componentes:**
- `PipelineProcess`: SEQUENTIAL / HIERARCHICAL
- Sequential: cada stage recebe `ctx[f"output_{stage_id}"]` do anterior
- Hierarchical: pula stages opcionais quando `ctx.get("action") == "HOLD"`
- `PipelineOutput.success`: False apenas quando stages requeridos falham
- Context propagation: `if isinstance(output, dict) and "action" in output: current_context["action"] = output["action"]`

**Exemplo hierárquico:**
```python
# VISION retorna {"action": "HOLD"} → IRONMAN é skipped
stages = [
    PipelineStage("VISION", vision_fn, required=True),
    PipelineStage("BATMAN", batman_fn, required=True),
    PipelineStage("IRONMAN", ironman_fn, required=False),  # skipped se action=HOLD
]
orchestrator = CyclePipelineOrchestrator(process=PipelineProcess.HIERARCHICAL, stages=stages)
result = orchestrator.kickoff(initial_context)
```

### Story 207 — MekkaAgentBackstory
**Arquivo:** `src/services/mekka_agent_backstory.py`
**Padrão:** CrewAI `Agent.backstory`

Registra e gerencia backstories de todos os agentes Mekka. Cada agente tem `role + goal +
backstory + performance_notes` que formam o system prompt injetado no LLM call.

**Personas padrão:**

| Agent | Role | Decision Style |
|-------|------|----------------|
| NICKFURY | Mission Commander — Mekka Trading Orchestrator | conservative |
| VISION | Elite Crypto Market Analyst — Strategic Signal Generator | balanced |
| BATMAN | Risk Guardian — Deterministic Risk Gate | conservative |
| IRONMAN | Execution Agent — Order & Position Manager | aggressive |

**System prompt gerado:**
```
# Role
{role}

# Goal
{goal}

# Background
{backstory}

# Recent Performance
- {note_1}
- {note_2}
- {note_3}   ← últimas 3 de até 10

# Current Context
{extra_context}
```

**Enriquecimento em Vision:**
```python
_enriched207 = _backstory207.build_system_prompt("VISION", _extra_ctx207)
if len(_enriched207) > 100:
    _effective_system_prompt = _enriched207 + "\n\n---\n\n" + _SYSTEM_PROMPT
```
O `_SYSTEM_PROMPT` original é preservado — o backstory **adiciona** contexto, não substitui.

**Performance notes adaptativas:**
```python
backstory.update_backstory("VISION", "Acerto 85% em regime BULL nas últimas 20 decisões")
# → adicionado ao final da seção "Recent Performance" do próximo LLM call
```
