## Stories Implementadas

### Story 178 — ArchitectEditorVision
**Padrão:** Aider architect/editor mode (dois modelos, dois papéis)

**Arquivo modificado:** `src/agents/vision.py`

Quando `settings.vision_architect_editor_enabled = True`, Vision faz **dois** LLM calls:
1. **Architect call** — prompt livre, gera thesis em 1-3 parágrafos (raciocínio sem restrições)
2. **Editor call** — thesis injetada no prompt, força conversão para TradingSignal JSON schema

Resultado: separação entre pensamento divergente (qual é o trade?) e execução estruturada
(qual é o JSON correto?). Reduz alucinações de estrutura em sinais complexos.

**Flag de controle:** `settings.vision_architect_editor_enabled` (default `False` — zero custo extra sem opt-in).

### Story 179 — AutoSignalLinter
**Padrão:** Aider auto-lint (linter corrige em vez de bloquear)

**Novo arquivo:** `src/services/auto_signal_linter.py`
**Arquivo modificado:** `src/agents/nick_fury.py`

`AutoSignalLinter` aplica 7 regras de correção ao `TradingSignal` pós-Vision, antes do StepGuard:

| Regra | Problema | Correção |
|-------|----------|----------|
| confidence_clamp | confidence < 0 ou > 1 | clamp [0, 1] |
| entry_price_positive | entry_price ≤ 0 | usa last_price se disponível |
| long_sl_tp_swap | LONG com SL > entry ou TP < entry | swap SL↔TP |
| short_sl_tp_swap | SHORT com SL < entry ou TP > entry | swap SL↔TP |
| leverage_clamp | leverage > settings.max_leverage | clamp ao máximo |
| risk_pct_clamp | risk_pct > settings.max_risk_per_trade_pct | clamp ao máximo |
| reasoning_fallback | reasoning ausente/vazio | adiciona nota de fallback |

`LintFix.to_search_replace()` gera o diff no formato Aider SEARCH/REPLACE para auditoria.

**Integração NickFury** (após Vision.run(), antes do StepGuard 166):
```python
signal = get_auto_signal_linter().lint_and_log(signal, last_price=_lint_price, symbol=symbol)
```

### Story 180 — TradeAnnotationWatcher
**Padrão:** Aider watch mode + AI! comments (file watcher para overrides do analista)

**Novo arquivo:** `src/services/trade_annotation_watcher.py`
**Arquivo modificado:** `src/agents/vision.py`

`TradeAnnotationWatcher` monitora `data/trade_hints.json` com **lazy reload por mtime**
(sem watchdog/inotify — funciona cross-platform). Recarrega o arquivo apenas quando
o timestamp de modificação muda.

`TradeHint` fields: `symbol`, `hint_text`, `strength` (weak/medium/strong), `expires_at` (ISO datetime opcional), `source`.

`get_prompt_block(symbol)` gera bloco formatado com emojis por strength:
- 🟡 weak, 🟠 medium, 🔴 strong

**Integração Vision** (antes do LLM call):
```python
_hint_block = get_trade_annotation_watcher().get_prompt_block(symbol)
if _hint_block:
    prompt = prompt + "\n\n" + _hint_block
```

`data/trade_hints.json` é lido em runtime — analistas podem editar o arquivo sem reiniciar o sistema.

### Story 181 — DynamicReasoningBudget
**Padrão:** Aider --thinking-tokens (budget de raciocínio adaptativo)

**Novo arquivo:** `src/services/dynamic_reasoning_budget.py`
**Arquivo modificado:** `src/agents/vision.py`

`DynamicReasoningBudget` mapeia regime × cap_tier → max_tokens para o LLM call Vision:

| Regime | Base tokens |
|--------|------------|
| VOLATILE | 4096 |
| BULL / BEAR / STRONG_BULL / STRONG_BEAR | 2048 |
| SIDEWAYS | 1024 |
| UNKNOWN | 2048 |

Multiplicadores por cap_tier: LARGE_CAP ×1.5, MID_CAP ×1.0, SMALL_CAP ×0.8.
Bounds: MIN=512, MAX=8192.

`BudgetDecision` expõe regime, cap_tier, base_tokens, multiplier, final_tokens, reasoning.

`get_reasoning_effort()` → "high" (≥3000), "medium" (≥1500), "low" — para passar como hint ao LLM.

**Nota:** `_vision_max_tokens` é calculado e logado; aplicação real ao `_call_llm` depende de
extensão futura do LLMClient para aceitar o parâmetro `max_tokens`.

### Story 182 — AnalysisPromptCache
**Padrão:** Aider prompt caching (contexto quente reduz latência de ciclos consecutivos)

**Novo arquivo:** `src/services/analysis_prompt_cache.py`
**Arquivo modificado:** `src/agents/vision.py`

`AnalysisPromptCache` é um cache em memória com TTL (default 600s = 10 min) para blocos
de prompt pré-computados:

- `store(key, content, ttl_seconds)` — armazena bloco
- `get(key)` → str | None — lê se não expirado (remove entrada expirada automaticamente)
- `get_or_build(key, builder, ttl_seconds)` — async/sync builder, armazena se retornar conteúdo
- `warm(builders)` — pre-aquece múltiplas entradas em paralelo via `asyncio.gather`
- `hit_rate` property + `summary()` com estatísticas de hits/misses/builds

Keys padrão: `"macro_context"`, `"regime_summary"`, `"open_interest_{SYM}"`, `"analyst_hints"`.

**Integração Vision** (antes do LLM call):
```python
_cached_macro = get_analysis_prompt_cache().get("macro_context")
if _cached_macro:
    prompt = prompt + "\n\n" + _cached_macro
```

Outros agentes podem popular `"macro_context"` via `cache.store(...)` no início do ciclo,
reduzindo latência de ~800ms para ~0ms nos ciclos subsequentes dentro do TTL.
