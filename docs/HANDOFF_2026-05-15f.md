### Por que total_count() como cursor SSE (Story 172)?

CycleEventLog mantém um deque rolling de N eventos (TTL/size bound).
`total_count()` é um contador monotônico acumulado — nunca decresce quando
o deque rotaciona eventos antigos. Usar `total_count()` como cursor garante
que o SSE detecta novos eventos mesmo quando eventos antigos saem do deque.

Se `total_count()` não existir na versão instalada, o fallback é
`len(log.last_n(1000))` — funcionalmente equivalente para deques pequenos.

### Por que symbol_filter.upper() no SSE handler (Story 172)?

Símbolos entram como `?symbol=btcusdt` (lowercase nos logs) ou `BTC` ou `BTCUSDT`.
O upper() normaliza antes de comparar com `getattr(e, "symbol", "").upper()`
para evitar falsos negativos.

### ObservabilityPlugin naming (Story 171)

Os @mekka_function são registrados com nome `obs__{fn_name}` pelo MekkaKernel
(prefixo de plugin). No get_tool_definitions(), aparecem como:
- `obs__get_cycle_events`
- `obs__get_signal_changes`
- `obs__get_context_window`
- `obs__get_step_guard_stats`
- `obs__get_validator_thresholds`

Invoke: `POST /api/kernel/invoke {"name": "obs__get_cycle_events", "arguments": {"symbol": "BTC"}}`
