## Story 208 — CycleStateGraph (LangGraph StateGraph)

**Arquivo:** `src/services/cycle_state_graph.py`

**O que faz:** Implementa o padrão StateGraph/CompiledGraph do LangGraph para o pipeline Mekka. Um typed state dict (`CycleState`) flui de nó em nó via arestas fixas ou condicionais. O grafo compilado tem guard de `max_steps=50` para evitar loops infinitos.

**Componentes principais:**

- `CycleState(dict)`: estado tipado do ciclo com propriedades `.action`, `.risk_approved`, `.has_errors`, `.initial()`, `.add_error()`, `.mark_visited()`
- `CycleStateGraph`: builder com `add_node()`, `add_edge()`, `add_conditional_edges()`, `set_entry_point()`, `set_finish_point()`, `compile()`
- `CycleCompiledGraph`: `invoke(state) → CycleState`, `stream(state) → Iterator[CycleState]`
- `END = "__END__"` constante global
- `build_default_mekka_graph()`: grafo padrão Vision→conditional→Batman→IronMan→END, com HOLD desviando Batman+IronMan

**Integração NickFury:** inicialização no bloco Stories 208-212, grafo disponível em `_state_graph208`.

## Story 209 — CycleConditionalRouter (LangGraph conditional_edges)

**Arquivo:** `src/services/cycle_conditional_router.py`

**O que faz:** Roteamento condicional por regras priorizadas com operadores e dotted-path evaluation. Equivalente ao `add_conditional_edges(router_fn)` do LangGraph.

**Componentes principais:**

- `RouterConditionOp` enum: `EQ / NEQ / GT / GTE / LT / LTE / IN / CONTAINS / TRUTHY / FALSY`
- `RouterCondition(field_path, op, value)`: avalia dotted path no estado (ex: `"signal.action"`, `"risk_report.approved"`)
- `RouterRule(destination, conditions, mode="ALL", priority=0)`: regra com modo AND/ANY
- `CycleConditionalRouter`: ordenado por priority descrescente, `route(state) → str`, `as_fn() → Callable`
- `build_vision_router()`: HOLD→END(20), confidence<0.4→END(15), LONG/SHORT+conf≥0.4→batman(10)
- `build_batman_router()`: approved→ironman(5), rejected→END(10)

**Integração NickFury:** `_router209 = build_vision_router(fallback="batman")`, resultado logado pós-Vision.

## Story 210 — CycleGraphCheckpointer (LangGraph MemorySaver)

**Arquivo:** `src/services/cycle_graph_checkpointer.py`

**O que faz:** Persiste snapshots do estado após cada nó do pipeline, com FIFO eviction por thread e suporte a time-travel replay. Equivalente ao `MemorySaver` do LangGraph.

**Componentes principais:**

- `CheckpointMeta`: `checkpoint_id, thread_id, node_name, step_number, has_errors`
- `CycleGraphCheckpointer`:
  - `save(thread_id, node_name, state) → str` — salva snapshot, evict FIFO se exceder `max_checkpoints_per_thread`
  - `load_latest(thread_id) → dict|None` — carrega checkpoint mais recente
  - `load(thread_id, checkpoint_id) → dict|None` — carrega checkpoint específico
  - `list_checkpoints(thread_id) → List[CheckpointMeta]`
  - `replay_from(thread_id, checkpoint_id) → Iterator[dict]` — time-travel replay
  - `delete_thread(thread_id) → bool`
- `wrap_with_checkpointer(compiled_graph, checkpointer) → CheckpointedGraph`

**Integração NickFury:** checkpoint salvo após Vision com `_checkpointer210.save(str(_cycle_id), "vision", _cp_state)`.

## Story 211 — CycleParallelBranch (LangGraph Send() API)

**Arquivo:** `src/services/cycle_parallel_branch.py`

**O que faz:** Executa análises multi-símbolo em paralelo (fan-out) e consolida resultados (fan-in). Equivalente ao `Send()` API do LangGraph para parallel branches.

**Componentes principais:**

- `FanInStrategy`: `MAX_CONFIDENCE / MAJORITY_VOTE / ALL`
- `BranchInput(symbol, state_override, metadata)`
- `BranchResult(symbol, state, elapsed_ms, success, error)` com propriedades `.action`, `.confidence`, `.signal`
- `CycleParallelBranch`:
  - `run(inputs, worker_fn) → List[BranchResult]` — via `ThreadPoolExecutor`
  - `run_async(inputs, worker_fn) → List[BranchResult]` — via `asyncio.gather`
  - `fan_in(results, strategy) → dict` — consolida: MAX_CONFIDENCE retorna sinal de maior confiança; MAJORITY_VOTE conta votos por ação; ALL retorna todos
- `_run_branch(inp, fn)` helper interno

**Integração NickFury:** `_parallel211 = get_cycle_parallel_branch()` disponível para análise multi-símbolo.

## Story 212 — CycleGraphInterrupt (LangGraph interrupt/Command)

**Arquivo:** `src/services/cycle_graph_interrupt.py`

**O que faz:** Pause/resume Human-in-the-Loop para o pipeline. Antes do IronMan executar uma ordem real, o sistema pode pausar e aguardar aprovação manual (via Telegram, dashboard, ou timeout). Equivalente ao `interrupt() + Command(resume=...)` do LangGraph.

**Componentes principais:**

- `InterruptStatus` enum: `PENDING / APPROVED / REJECTED / TIMEOUT / SKIPPED`
- `InterruptRecord`: `interrupt_id, cycle_id, node_name, signal, timeout_at, on_timeout`, `.is_expired`, `.remaining_s`, `.to_dict()`
- `CycleGraphInterrupt`:
  - `request(cycle_id, node_name, signal, timeout_s, on_timeout) → str`
  - `resolve(interrupt_id, decision, reason) → bool`
  - `check(interrupt_id) → InterruptStatus` — aplica timeout automático se expirado
  - `get(interrupt_id) → InterruptRecord|None`
  - `list_pending() → List[InterruptRecord]`
  - `auto_expire_pending() → int`
  - `wait_for_resolution(interrupt_id, poll_interval, max_wait_s)` — síncrono
  - `wait_for_resolution_async(interrupt_id, poll_interval)` — assíncrono
- `_apply_timeout()`: `on_timeout="approve"→APPROVED`, else `→TIMEOUT`

**Integração NickFury:** `_interrupt212 = get_cycle_graph_interrupt()`, `auto_expire_pending()` chamado a cada ciclo.

1. **CSP bloqueando Hyperliquid** — `connect-src` em `_DEFAULT_CSP` não incluía `api.hyperliquid.xyz`. Corrigido adicionando origens HTTP e WS para mainnet e testnet.

