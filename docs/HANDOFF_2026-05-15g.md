## Notas técnicas

### Por que VisionPlugin.generate_signal é só um hook (Story 174)?

A Vision.run() recebe um objeto `Analysis` complexo (chart, indicators, layer1 scores).
Serializar esse objeto para JSON e reconstruí-lo dentro do plugin seria frágil e quebraria
se Analysis mudar. O design correto é manter a call direta no NickFury e usar o hook apenas
para disparar a FilterChain. Quando um filtro de logging/benchmarking está registrado, ele
dispara antes do Vision.run() sem saber dos detalhes de Analysis.

### Por que `_filter_chain is not None` é necessário (Story 174)?

Por padrão o MekkaKernel não tem filter chain. Invocar `kernel.invoke("vision", ...)` sem
filter chain é equivalente a chamar o plugin diretamente — e o generate_signal faz I/O
(consulta CycleEventLog) que é desnecessário em produção sem filtros. O guard evita esse
overhead quando não há filtros configurados.

### URL do EventSource com seed (Story 173)?

`?last=10` faz o servidor enviar os 10 eventos mais recentes como seed antes de iniciar
o streaming live. Isso permite que o panel mostre estado atual imediatamente ao abrir,
sem esperar pelo próximo ciclo (que pode levar até 4h).

### /api/obs/* vs /api/kernel/invoke (Story 175)?

`/api/kernel/invoke` é POST e genérico — qualquer tool, qualquer plugin. `/api/obs/*` é
GET e auto-documenta: a URL diz o que retorna. Mais fácil de bookmarkar, monitorar com
cron/Grafana, ou chamar via `curl`. Ambos coexistem sem conflito.
